# 不審発言検知の評価（#13）

## 目的と現在の状態

架空の会話で見逃し・誤警告を調べ、プロンプト調整前後を同じ条件で比較する。
実在の組織・個人・患者の情報は使用しない。現時点ではサンプルと評価処理を準備した段階で、
Geminiの25件評価や、その結果に基づくプロンプト調整はまだ行っていない。
#12の接続・Firestore対応は [中断時のメモ](issue12-handoff.md) から再開する。

## データセットと台本

`samples/conversations/analyze-cases.json` に25ケースを保存。

| 種別 | 件数 | 期待する表示 |
| --- | --- | --- |
| 不審な会話 | 10 | high・即時警告 |
| 通常の診療会話 | 10 | low・即時警告なし |
| 紛らわしい会話 | 5 | medium・即時警告なし、終了後レポート |

各ケースは6発言で、先頭1件は挨拶。5件以上の入力から末尾5件を選ぶ分析条件に合わせ、
判断に必要な情報は末尾5件内に置く。話者はtext内の「担当者：」「患者：」で示す。
`utterances[].text` を開始秒数順に読み上げれば、#21の音声デモ用台本として使える。
実際の音声やTTSは今回生成していない。

`expected` にrisk_level・is_suspicious・category・即時警告の期待値を付けた。
`evidence_hint` は人による根拠レビューの補助であり、引用の完全一致を正解条件にはしない。
軽い注意のlowはis_suspicious=trueとカテゴリ・引用を持つ。通常会話のlowはfalse・nullで区別する。
既存の通常会話10件は根拠なしのlowであり、軽い注意の正例とは別に扱う。
ラベルは担当者レビュー前の案。紛らわしい例は特に複数人で確認してから正解を固定する。

調整用tuningが16件、未調整評価用holdoutが9件。プロンプト変更にはtuningのみを使用し、
holdoutの結果を見て調整した場合は、別の未使用会話を追加して最終評価する。

## 実行方法

リポジトリのルートで以下を実行する。既定では課金もFirestoreアクセスも発生しない。

```bash
.venv/bin/python scripts/evaluate_analysis.py
```

評価処理の疎通確認（固定モック。精度評価には使用しない）：

```bash
.venv/bin/python scripts/evaluate_analysis.py --run --backend mock --limit 2
```

実際のGemini評価は、チームで件数と費用を確認してから明示的に実行する。

```bash
# 初回は調整用の少数ケース
.venv/bin/python scripts/evaluate_analysis.py --run --limit 2 --tag before
# 調整用16ケース
.venv/bin/python scripts/evaluate_analysis.py --run --split tuning --tag before
# プロンプト変更後、同じ条件で比較
.venv/bin/python scripts/evaluate_analysis.py --run --split tuning --tag after
# 調整後の独立評価9ケース
.venv/bin/python scripts/evaluate_analysis.py --run --split holdout --tag final
```

ローカルプロセス内のFastAPI `/analyze` を経由し、認証・入力・出力・引用検証を通す。
実分析時も状態管理だけは一時SQLiteに固定し、Firestoreへ読み書きしない。
ケースごとに新しいsessionIdを作り、他の通話の分析済みIDに影響しない。
これはAI判定の評価であり、本番Firestore・録音・文字起こし・警告UIの結合テストではない。

`--run`の既定backendはvertexai。モデル・ADC・プロジェクトは既存設定を利用する。
再試行は現在の設定に従うため、選択ケース数よりAI呼出回数が多くなることがある。
発言本文をアプリログには追加せず、架空サンプルの入力・出力を評価成果物として保存する。

## 保存する履歴

`output/evaluation/<実行日時>/` に以下を保存し、Gitには自動追加しない。

- `run.json`：モデル、リージョン、分割、件数、再試行設定、データ・プロンプト・スキーマのハッシュ
- `prompt.txt`：実行時のシステムプロンプト
- `results.jsonl`：各ケースの開始・完了、入力、期待値、結果、HTTP状態、所要時間、usage_metadata
- `summary.json`：件数集計と取得できたトークン数の合計
- `results.md`：ケースごとの比較表

開始と完了のJSONLは追記・flush/fsyncし、途中で失敗しても完了済みケースの記録を残す。
強制終了時は開始だけのケースが残る可能性がある。ローカル保存でありバックアップではない。

## 評価指標

| 指標 | 数え方 |
| --- | --- |
| 即時警告の見逃し | 期待highなのにhighが返らない件数。技術的失敗も含めて記録 |
| 通常会話への誤警告 | 期待lowにhighを返した件数 |
| 通常会話の誤った要確認扱い | 期待is_suspicious=falseなのにtrueを返した件数（軽い注意のlowも含む） |
| 軽い注意の見逃し | 期待low・trueなのにfalseを返した、または技術的失敗となった件数 |
| 曖昧な会話への過剰警告 | 期待mediumにhighを返した件数 |
| 技術的失敗 | 200以外、空応答、不正JSON・スキーマ・引用エラー等。lowに変換しない |
| risk/category一致 | 正常応答で期待ラベルと一致した件数。正常応答数も併記 |
| 処理時間・使用量 | 各ケースのAPI処理時間と、取得できた入力・回答・推論トークン数 |

分母は対象の期待ラベル件数とする。対象0件の率は算出不能とし、100%とはしない。
正常応答だけで高精度に見せず、技術的失敗と全体件数を必ず併記する。
reason・adviceの自然さ、断定、根拠の不足、危険な案内は人が別途レビューする。
この少数の作例で実際の診療に対する精度・安全性を保証しない。
