# #12 中断時の引継ぎ（#13へ先行）

## 実装と確認済み

- `/analyze`からVertex AIに直近5件の発言本文を送信し、#11のJSON・引用を検証する処理。
- 実接続で合成の暗証番号要求→high/C2、症状確認→lowを確認済み。
- 実行時の入力・応答・usage_metadataは `output/analysis-history/requests.jsonl` に保存済み。
- 初回も以降も新しい発言5件で分析する（5件、10件、15件の時点）。末尾5件すべてが未分析の場合だけ呼び出す。
- 待機は204、成功時のみ分析済みにし、失敗時は予約解除。拡張側に204の処理を追加済み。
- ローカルSQLite版に加え、Firestoreの通話単位トランザクションによる共有管理を実装。
- auto設定はvertexaiならFirestore、mockならSQLite。Firestore障害時の自動フォールバックなし。
- 通常テスト122件成功、Emulator統合テスト4件は別実行で成功。実Firestoreの予約・保存成功はまだ未確認。

## Firestoreで止まっている点

- 対象の既存GCPプロジェクトは `.env` の `GOOGLE_CLOUD_PROJECT` / `GCP_PROJECT_ID`。
- 実接続で `(default)` DBが存在しない404を確認。DB一覧も空だった。
- `(default)` / Standard / Native / asia-northeast1 を作成する承認待ちで操作が中断された。
- 中断後の作成有無は未確認。作成前に必ずDB一覧を確認し、チームとDB・リージョンを合わせる。
- APIはストア障害で503にし、AIを呼ばずに止まる。

## 再開時

1. DBの有無とチームの保存先、実行主体のIAM権限を確認。
2. Firestore予約→Gemini→完了更新→同じIDの再送が204、を実環境で確認。
3. 実行履歴とusage_metadataを保存し、読み書き・費用を実測。
4. 文字起こし側のID維持、start_sec→startSec変換、自動送信と接続。
5. 警告・保存・終了後レポート側と、対象発言の紐付けや重複防止を調整。

Firestoreは `analysis_states/{SHA256(sessionId)}`、通話ごとに1文書。
待機は基本1読取、分析予約と完了で基本2読取・2書込（競合・再試行は別）。
本文は保存せず分析済みIDハッシュを最大2000件保持。上限超過は503で止め、保存期限・削除方針は未確定。
Geminiの自動再試行は文字起こしの再実行ではない。同じ音声の再文字起こしでIDが変わる問題は別途対策が必要。

コミット・pushはユーザーが行う方針。現在の未コミット差分と `.env.example` の既存変更を混同しない。
#13は [評価手順](evaluation.md) にまとめ、AI評価時も一時SQLiteを使ってFirestoreの使用量と分離する。
